# Grand Mobile Support Copilot

Локальный MVP для кейса 03 Decentrathon 6.0: сервис получает обращение игрока, определяет категорию и приоритет, находит подходящий пункт в переданных правилах и готовит осторожный черновик ответа. Решение **не принимает вердикты и не отправляет ответы игрокам**.

Это стартовый эвристический baseline, а не обученная модель. Без `tickets_train.jsonl.gz`, `tickets_valid.jsonl` и оценки специалистов качество на реальных обращениях неизвестно. В частности, качество казахских и узбекских текстов и релевантность найденных правил нужно отдельно проверить людьми. Исправленный промпт для возможного будущего подключения LLM находится в [PROMPT.md](PROMPT.md); текущая версия его не использует.

## Быстрый запуск

Нужны Python 3.10+ и `make`; сторонние пакеты и внешние API не требуются.

1. Положите выданные организаторами файлы в **непубликуемую** директорию:

   ```text
   data/
     rules.json
     taxonomy.json
   ```

2. Запустите сервис:

   ```bash
   make serve
   ```

3. Откройте предпросмотр, предоставленный рабочей средой, или `http://127.0.0.1:8000` на той машине, где запущен сервер. В интерфейсе есть синтетические примеры, форма обращения и очередь текущей сессии. Кнопка «Очистить форму» сбрасывает ввод, но не удаляет результаты из очереди.

API доступен по `POST /triage`, проверка состояния — `GET /health`. Пример для локальной машины:

```bash
curl -X POST http://127.0.0.1:8000/triage \
  -H 'Content-Type: application/json' \
  -d '{"kind":"complaint","messages":[{"role":"player","text":"Игрок оскорбил меня в чате","attachments":1}]}'
```

Ответ содержит `lang`, `category`, `priority`, `is_spam_or_duplicate`, `extracted`, `draft_reply`, `needs_human`, `confidence` и `reasons` по контракту кейса. `confidence` — **эвристическая оценка**, а не откалиброванная вероятность.

Пути к файлам и порт можно поменять:

```bash
make serve RULES=/private/rules.json TAXONOMY=/private/taxonomy.json PORT=8000
```

## Пакетный запуск и оценка

```bash
make predict IN=data/tickets.jsonl OUT=data/pred.jsonl
make evaluate IN=data/tickets_valid.jsonl
make test
```

`predict` принимает JSONL и JSONL.GZ, выдаёт одну строку на обращение в исходном порядке и сохраняет `ticket_id`, если он был во входе. Выходной файл записывается атомарно, входной файл не перезаписывается. Можно использовать `-` для stdin/stdout через `python -m support_copilot.batch --help`.

Оценка считает accuracy категории и macro-F1 приоритета **только там, где разметка действительно присутствует**; при её отсутствии метрики равны `null`. Также выводятся доля обращений для человека, доля черновиков со ссылками и p95 времени локального конвейера. Это время не включает HTTP и инфраструктуру. Слепая оценка черновиков, релевантность ссылок и языковое качество требуют отдельной проверки. Шаблон отчёта — [REPORT.md](REPORT.md).

## Как работает MVP

- При классификации используются текст игрока, примеры и категории из `taxonomy.json` и небольшой набор многоязычных эвристик. Ответы администраторов и поля `verdict`, `punishment`, `violation`, `category` и `priority` **не используются как признаки** при предсказании.
- Поиск — локальный извлекающий RAG: нумерованные пункты выделяются из `rules.json`, кандидаты ограничиваются правилами категории, а затем ранжируются по совпадению слов и контексту. Совпадающие номера из разных разделов не смешиваются; название раздела указано в черновике. Если подходящий пункт не подтверждён, ссылка не придумывается, а черновик помечается как не готовый к отправке.
- Предположения игрока и его ссылки на правила не считаются доказанными фактами. `has_evidence: true` означает, что доказательства упомянуты игроком или указаны в метаданных вложений; поле `reasons` поясняет разницу. Отрицания вроде «скриншотов нет» учитываются, если метаданные не указывают на вложение. Содержимое скриншотов сервис не видит ни при каком значении поля. В `server` возвращается строковый идентификатор сервера, а при его отсутствии — явно указанная `region`.
- Используются короткие шаблоны RU/KK/UZ/EN/ES/PT. Для казахского текста учитываются замены символов из условия. Английский, испанский и португальский определяются эвристически; короткие и смешанные сообщения могут быть определены неверно.
- Платежи, подозрения на взлом и блокировки, **которые удалось распознать**, направляются человеку. Все жалобы и почти все другие обращения тоже требуют проверки; автоматическое уточнение допускается только для простого приветствия. Неясные просьбы о помощи передаются человеку. Распознавание эвристическое и не гарантирует выявление всех рискованных формулировок.
- Пятый похожий тикет того же `reporter_hash` за час помечается как дубликат. Состояние хранится в памяти процесса, без текста сообщений; без хэша заявителя, между разными процессами и после перезапуска надёжного обнаружения дубликатов нет. Для пакетной обработки вход должен идти по возрастанию `created_at`, иначе более поздние обращения не учитываются как предыдущие.
- Интерфейс позволяет редактировать и копировать черновики, а также отмечать их для проверки. Очередь и правки существуют **только в текущем окне**: интеграции с игрой, реальной отправки и сохранения обучающей обратной связи пока нет.

### Необязательная база знаний

Отдельная база знаний не была приложена. Сервис может использовать локальный файл с проверенными статьями формата ниже; содержание здесь только синтетический пример:

```json
{
  "articles": [
    {"id": "sample-1", "title": "Справочная статья", "text": "Текст проверенной инструкции.", "categories": ["report.question"]}
  ]
}
```

Запуск: `make serve KNOWLEDGE=data/knowledge.json` или `make predict IN=... OUT=... KNOWLEDGE=data/knowledge.json`. Статья подбирается по словам, а пригодный русский отрывок включается в черновик с передачей человеку. Это не замена проверенной многоязычной базе знаний.

## Конфиденциальность и ограничения

Папка `data/`, JSONL и типичные файлы результатов исключены из Git. Не публикуйте исходные файлы, содержимое обращений, цитаты из набора, предсказания или производные выборки; проверяйте `git status` перед публикацией. Данные предназначены только для кейса и должны быть удалены в течение 14 дней после объявления победителей, если нет отдельного соглашения. В запросы к сторонним API данные не отправляются.

В приложенной таксономии указано, что она черновая. До сдачи стоит уточнить у организаторов её окончательную версию и наличие размеченных категорий и приоритетов в валидации: описание датасета и пример схемы в задании противоречат друг другу.

Встроенный HTTP-сервер предназначен для демонстрации в доверенной среде: аутентификации, постоянной очереди, отказоустойчивости и интеграции с игрой нет. Не размещайте его в открытом доступе с данными кейса; перед настоящим использованием нужны защищённый сервер, контроль доступа, проверка безопасности и оценка на реальной разметке.
