# Grand Mobile Support Copilot

Локальный MVP для кейса 03 Decentrathon 6.0: сервис получает обращение игрока, определяет категорию и приоритет, находит подходящий пункт в переданных правилах и готовит осторожный черновик ответа. Решение **не принимает вердикты и не отправляет ответы игрокам**.

Это стартовый эвристический baseline, а не обученная модель. Без `tickets_train.jsonl.gz`, `tickets_valid.jsonl` и оценки специалистов качество на реальных обращениях неизвестно. В частности, качество казахских и узбекских текстов и релевантность найденных правил нужно отдельно проверить людьми. Исправленный промпт для возможного будущего подключения LLM находится в [PROMPT.md](PROMPT.md); текущая версия его не использует.

## Быстрый запуск

Нужны Python 3.10+ и `make`; сторонние пакеты и внешние API не требуются.

1. Положите выданные организаторами файлы в **непубликуемую** директорию:

   ```text
   data/
     rules.json
     taxonomy.json
   ```

2. Запустите сервис:

   ```bash
   make serve
   ```

3. Откройте предпросмотр, предоставленный рабочей средой, или `http://127.0.0.1:8000` на той машине, где запущен сервер. В интерфейсе есть синтетические примеры, форма обращения и очередь текущей сессии. Переключатель в верхней панели доступен на страницах оператора и администратора: **русский / English / қазақша**. Выбранный язык интерфейса запоминается в браузере.

   Текст игрока, черновики, цитаты правил и исходный JSON не переводятся переключателем: они остаются без изменений. Язык подготовленного ответа зависит от определённого языка игрока, а не языка интерфейса. Оригинальные цитаты правил могут оставаться на языке источника и требуют проверки человеком.

   Для жюри откройте ссылку **«Как работает система»** в верхнем блоке или **«О помощнике»** в навигации. Раздел объясняет путь обращения, роль администратора, локальную и серверную очереди, приватность и ограничения прототипа. Он также доступен на всех трёх языках интерфейса.

4. Панель администратора — отдельная страница `http://127.0.0.1:8000/admin`; ссылки из операторской страницы открывают её в той же вкладке, чтобы после возврата восстановить очередь. При первом запуске сервер создаёт случайный ключ в `data/admin.key`. Откройте файл **на компьютере сервера**, скопируйте ключ в форму входа и никому его не передавайте. В Windows вместо `make` можно использовать:

   ```powershell
   py -m support_copilot.server --host 127.0.0.1 --port 8000
   ```

   После запуска в другом окне PowerShell: `notepad .\data\admin.key`. Файл ключа и очередь исключены из Git. Если ключ задан через `COPILOT_ADMIN_TOKEN`, используйте его вместо файла.

API доступен по `POST /triage`, проверка состояния — `GET /health`. Пример для локальной машины:

```bash
curl -X POST http://127.0.0.1:8000/triage \
  -H 'Content-Type: application/json' \
  -d '{"kind":"complaint","messages":[{"role":"player","text":"Игрок оскорбил меня в чате","attachments":1}]}'
```

Ответ содержит `lang`, `category`, `priority`, `is_spam_or_duplicate`, `extracted`, `draft_reply`, `needs_human`, `confidence` и `reasons` по контракту кейса. `confidence` — **эвристическая оценка**, а не откалиброванная вероятность.

Пути к файлам и порт можно поменять:

```bash
make serve RULES=/private/rules.json TAXONOMY=/private/taxonomy.json PORT=8000
```

## Ручная проверка и ошибки обработки

- HTTP-сервис автоматически помещает в отдельную серверную очередь обращения с `needs_human: true`. Критический приоритет, низкая уверенность, неопределённый язык, возможный спам/повтор и категории обязательной проверки дополнительно направляются человеку. Текущий классификатор — эвристический baseline, не LLM; он не умеет обнаруживать все свои смысловые ошибки. Оператор может вручную отправить любое обращение через кнопку в результате.
- Если обработчик выбросил исключение или вернул некорректный результат, обращение попадает в очередь без выдуманных категории, приоритета и ответа. Если правила или таксономия не загрузились при запуске, сервер работает в режиме ручной проверки; после исправления файлов его нужно перезапустить. В интерфейсе при тайм-ауте также предпринимается отдельная попытка передачи в очередь.
- Администратор видит причину передачи и сообщение игрока, может взять обращение в работу, исправить и сохранить черновик, а затем нажать «Отправить оператору». Ответ появляется в доступной операторской очереди; его можно скопировать или перенести в черновик. Игроку ответ не отправляется автоматически.
- Очередь оператора, выбранное обращение, форма, черновики и идентификаторы для получения ответов сохраняются в `sessionStorage` **этой вкладки**. После обновления и перехода в админку и обратно очередь восстанавливается, а статусы переданных обращений запрашиваются снова. Она не синхронизируется между вкладками и может пропасть при закрытии вкладки, очистке данных браузера или недоступном/переполненном хранилище. При ошибке хранения показывается предупреждение; не считайте данные сохранёнными. При незавершённой операции дождитесь её результата перед переходом.
- `sessionStorage` не шифрует данные и может содержать текст игрока, введённый хеш, черновики, ответы и секретные идентификаторы доступа к статусу. Не используйте общий компьютер для личных данных и ограничьте доступ к профилю браузера. Некоторые браузеры восстанавливают закрытые вкладки вместе с хранилищем — закрытие не является надёжным стиранием. Кнопка «Очистить очередь» с подтверждением удаляет локальную очередь и доступ к ответам в этой вкладке, **не удаляя записи с сервера**. «Очистить форму» отдельно сбрасывает введённые текст, вложения и хеш. Серверные записи и скачанные выгрузки удаляются отдельно по правилам проекта.
- Кнопка «Эскалировать» сохраняет текущий черновик и помечает обращение для дополнительной проверки в той же очереди; его можно найти фильтром «Эскалации». Это внутренняя отметка: отдельные роли, назначения и внешние уведомления не подключены. Статус доступен оператору, но черновик не считается готовым ответом.
- В серверную очередь сначала попадает исходный черновик. Локальные правки оператора передаются только после нажатия «Передать правку администратору». Администратор видит их отдельно. Проверка версии не позволяет одному администратору незаметно затереть изменения другого.
- При полной недоступности сервера доставка невозможна; при обрыве связи подтверждение может потеряться. Интерфейс не объявляет такую передачу успешной и позволяет повторить попытку с тем же идентификатором без создания дубликата. Администратор должен следить за своей очередью: внешних уведомлений, SMS, Telegram и интеграции с игрой нет.
- При успешном `POST /triage` JSON результата остаётся прежним. Заголовок `X-Review-Status` содержит `queued`, `not_required` или `unavailable`; при `queued` заголовок `X-Review-Receipt` позволяет запросить `/reviews/status` через одноимённый заголовок. Он же возвращается при ошибке обработки, если обращение действительно сохранено. Идентификатор является секретом доступа к статусу и ответу: не помещайте его в URL, логи или общие чаты. При `unavailable` нельзя считать обращение доставленным. Пакетная команда `make predict` не добавляет обращения в эту очередь.

Данные серверной очереди хранятся в `data/admin-queue.sqlite3`, включая текст игрока, ограниченные метаданные, исходный результат и правки администратора. Хеши заявителей, ответы других ролей, содержимое вложений и тексты исключений не сохраняются. По умолчанию допускается до 1000 записей; заполненная очередь не удаляет действующие обращения молча. Записи старше 14 дней удаляются при следующем обращении к очереди, а администратор может удалить запись вручную. **Это не отменяет обязанности владельца удалить все данные и резервные копии в срок, установленный организаторами.**

### Обратная связь для будущего обучения

- После сохранения изменённого черновика, эскалации с правкой или отправки ответа оператору в той же базе атомарно сохраняется обратная связь. Для каждого обращения хранится **последнее** состояние: текст игрока, исходный ответ помощника (если он был), переданный оператором черновик, ответ администратора, версия и статус. Простое взятие в работу без правки обучающую запись не создаёт; отправка неизменённого ответа фиксируется как подтверждение без исправления.
- Раздел «Обратная связь» в админке выгружает записи в `admin-feedback.jsonl`. Эндпоинт `GET /admin/api/feedback/export` требует ключ администратора. В строках `approved: true` означает, что текущая версия ответа передана оператору; `false` — черновик или эскалация. `is_current: false` означает, что после сохранения сигнала карточка изменилась и требует повторной проверки. `feedback_type` различает исправленный, неизменённый и полностью человеческий ответ. Это сырая обратная связь, не гарантия правильной разметки.
- При повторном открытии завершённого обращения подтверждение снимается. Удаление или автоматическая очистка обращения удаляет и связанную запись обратной связи. **Уже скачанные выгрузки не удаляются автоматически:** они содержат обращения и ответы, поэтому храните их приватно, не коммитьте и удаляйте вместе с другими данными по срокам организаторов. Безопасно проверить обезличивание и качество перед любым использованием.
- Текущие эвристики не обучаются и не изменяются автоматически. Выгрузка — исходный материал для будущего обучения, которое необходимо отдельно разработать и оценить; не используйте неподтверждённые или устаревшие записи как готовые эталоны.

На Unix созданные файл ключа и база имеют права `600`, новая папка — `700`. На Windows проверьте права доступа к папке средствами ОС: `chmod` не заменяет настройки ACL. Ключ создаётся только на сервере, не передаётся в URL и не сохраняется в браузерном хранилище; при перезагрузке админки или уходе с неё нужно войти заново. При возврате через историю браузера ключ и карточки не восстанавливаются из back/forward cache (кроме специального изолированного демо без входа). Доступен собственный ключ в переменной окружения `COPILOT_ADMIN_TOKEN` (24–200 ASCII-символов без пробелов, буквы, цифры и `._~-`) и параметры `--admin-db`, `--admin-key-file`. Используйте отдельную учётную запись ОС и ограничьте доступ к файлам ключа и базы.


### Необязательная браузерная проверка

Основные тесты `make test` не требуют Node.js. Для сквозной проверки очереди, возврата из админки, языков и ошибок `sessionStorage` можно запустить `tests/browser_session_i18n.cjs` с Node.js, `puppeteer-core` и Chromium. Тест создаёт синтетические обращения, поэтому запускайте его **только на отдельной тестовой базе**, а не на рабочем сервере. Пример для Linux/macOS с уже установленным Chromium:

```bash
npm install --prefix /tmp/copilot-browser-deps puppeteer-core
COPILOT_ADMIN_TOKEN=synthetic-integration-admin-key-12345 \
  python3 -m support_copilot.server --host 127.0.0.1 --port 8012 --admin-db /tmp/copilot-e2e.sqlite3
# В другом терминале:
NODE_PATH=/tmp/copilot-browser-deps/node_modules CHROME_PATH=/path/to/chromium \
  TEST_ADMIN_KEY=synthetic-integration-admin-key-12345 node tests/browser_session_i18n.cjs
```

`TEST_BASE_URL` можно задать для другого адреса изолированного тестового сервера. Не используйте реальный ключ. Тестовая база и загруженные зависимости не входят в репозиторий.

`predict` принимает JSONL и JSONL.GZ, выдаёт одну строку на обращение в исходном порядке и сохраняет `ticket_id`, если он был во входе. Выходной файл записывается атомарно, входной файл не перезаписывается. Можно использовать `-` для stdin/stdout через `python -m support_copilot.batch --help`.

Оценка считает accuracy категории и macro-F1 приоритета **только там, где разметка действительно присутствует**; при её отсутствии метрики равны `null`. Также выводятся доля обращений для человека, доля черновиков со ссылками и p95 времени локального конвейера. Это время не включает HTTP и инфраструктуру. Слепая оценка черновиков, релевантность ссылок и языковое качество требуют отдельной проверки. Шаблон отчёта — [REPORT.md](REPORT.md).

## Как работает MVP

- При классификации используются текст игрока, примеры и категории из `taxonomy.json` и небольшой набор многоязычных эвристик. Ответы администраторов и поля `verdict`, `punishment`, `violation`, `category` и `priority` **не используются как признаки** при предсказании.
- Поиск — локальный извлекающий RAG: нумерованные пункты выделяются из `rules.json`, кандидаты ограничиваются правилами категории, а затем ранжируются по совпадению слов и контексту. Совпадающие номера из разных разделов не смешиваются; название раздела указано в черновике. Если подходящий пункт не подтверждён, ссылка не придумывается, а черновик помечается как не готовый к отправке.
- Предположения игрока и его ссылки на правила не считаются доказанными фактами. `has_evidence: true` означает, что доказательства упомянуты игроком или указаны в метаданных вложений; поле `reasons` поясняет разницу. Отрицания вроде «скриншотов нет» учитываются, если метаданные не указывают на вложение. Содержимое скриншотов сервис не видит ни при каком значении поля. В `server` возвращается строковый идентификатор сервера, а при его отсутствии — явно указанная `region`.
- Используются короткие шаблоны RU/KK/UZ/EN/ES/PT. Для казахского текста учитываются замены символов из условия. Английский, испанский и португальский определяются эвристически; короткие и смешанные сообщения могут быть определены неверно.
- Платежи, подозрения на взлом и блокировки, **которые удалось распознать**, направляются человеку. Все жалобы и почти все другие обращения тоже требуют проверки; автоматическое уточнение допускается только для простого приветствия. Неясные просьбы о помощи передаются человеку. Распознавание эвристическое и не гарантирует выявление всех рискованных формулировок.
- Пятый похожий тикет того же `reporter_hash` за час помечается как дубликат. Состояние хранится в памяти процесса, без текста сообщений; без хэша заявителя, между разными процессами и после перезапуска надёжного обнаружения дубликатов нет. Для пакетной обработки вход должен идти по возрастанию `created_at`, иначе более поздние обращения не учитываются как предыдущие.
- Интерфейс позволяет редактировать и копировать черновики. Локальная очередь оператора привязана к текущей вкладке и сохраняется при её обновлении и переходах; переданные на ручную проверку обращения, ответы администратора и последняя версия обратной связи сохраняются в отдельной серверной очереди. Интеграции с игрой, отправки игрокам и автоматического обучения пока нет.

### Необязательная база знаний

Отдельная база знаний не была приложена. Сервис может использовать локальный файл с проверенными статьями формата ниже; содержание здесь только синтетический пример:

```json
{
  "articles": [
    {"id": "sample-1", "title": "Справочная статья", "text": "Текст проверенной инструкции.", "categories": ["report.question"]}
  ]
}
```

Запуск: `make serve KNOWLEDGE=data/knowledge.json` или `make predict IN=... OUT=... KNOWLEDGE=data/knowledge.json`. Статья подбирается по словам, а пригодный русский отрывок включается в черновик с передачей человеку. Это не замена проверенной многоязычной базе знаний.

## Конфиденциальность и ограничения

Папка `data/`, JSONL и типичные файлы результатов исключены из Git. Не публикуйте исходные файлы, содержимое обращений, цитаты из набора, предсказания или производные выборки; проверяйте `git status` перед публикацией. Данные предназначены только для кейса и должны быть удалены в течение 14 дней после объявления победителей, если нет отдельного соглашения. В запросы к сторонним API данные не отправляются.

В приложенной таксономии указано, что она черновая. До сдачи стоит уточнить у организаторов её окончательную версию и наличие размеченных категорий и приоритетов в валидации: описание датасета и пример схемы в задании противоречат друг другу.

Встроенный HTTP-сервер предназначен для демонстрации в доверенной среде. Админка защищена одним локальным ключом, но полноценного управления пользователями, TLS, аудита, резервирования, независимого канала доставки и аутентификации обычного `/triage` нет. `make serve` слушает `0.0.0.0` для предпросмотра; для работы на своём ПК используйте команду с `--host 127.0.0.1`. Не размещайте приложение в открытом доступе с данными кейса; перед реальным использованием нужны защищённый сервер, отдельные учётные записи и роли, HTTPS, контроль доступа, проверка безопасности и оценка на реальной разметке.
