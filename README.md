# Grand Mobile Support Copilot

Локальный MVP для кейса 03 Decentrathon 6.0: сервис получает обращение игрока, определяет категорию и приоритет, находит подходящий пункт в переданных правилах и готовит осторожный черновик ответа. Решение **не принимает вердикты и не отправляет ответы игрокам**.

Это стартовый эвристический baseline, а не обученная модель. Обработано 1000 предоставленных обращений, но меток категорий и приоритетов в них нет: качество классификации и релевантность цитат не подтверждены. Отдельная база знаний и оценки специалистов пока не предоставлены, поэтому полное соответствие кейсу **не подтверждено**. Подробные результаты и ограничения — в [REPORT.md](REPORT.md). Промпт для возможного будущего подключения LLM находится в [PROMPT.md](PROMPT.md); текущая версия его не использует.

## Быстрый запуск

Нужны Python 3.10+ и `make`; сторонние пакеты и внешние API не требуются.

1. Положите выданные организаторами файлы в **непубликуемую** директорию:

   ```text
   data/
     rules.json
     taxonomy.json
     knowledge.json    # когда будет предоставлена проверенная база знаний
   ```

2. Запустите сервис:

   ```bash
   make serve
   ```

3. Откройте предпросмотр, предоставленный рабочей средой, или `http://127.0.0.1:8000` на той машине, где запущен сервер. В интерфейсе есть синтетические примеры, форма обращения и очередь текущей сессии. Переключатель в верхней панели доступен на страницах оператора и администратора: **русский / English / қазақша**. Выбранный язык интерфейса запоминается в браузере.

   Переключатель меняет только интерфейс: текст игрока, существующие черновики, цитаты и исходный JSON он не переводит. Отдельное поле **«Язык автоответа»** позволяет выбрать русский, английский или казахский для нового черновика; по умолчанию используется определённый язык игрока. Если он не определён, без явного выбора используется русский и требуется проверка. В автоматическом режиме сохраняется и прежняя поддержка UZ/ES/PT. Это локальные шаблоны, а не нейросеть или переводчик: качество языка и смысл ответа должен проверить человек, цитаты правил остаются на языке источника.

   Для жюри откройте ссылку **«Как работает система»** в верхнем блоке или **«О помощнике»** в навигации. Раздел объясняет путь обращения, роль администратора, локальную и серверную очереди, приватность и ограничения прототипа. Он также доступен на всех трёх языках интерфейса.

4. Панель администратора — отдельная страница `http://127.0.0.1:8000/admin`; ссылки из операторской страницы открывают её в той же вкладке, чтобы после возврата восстановить очередь. При первом запуске сервер создаёт случайный ключ в `data/admin.key`. Откройте файл **на компьютере сервера**, скопируйте ключ в форму входа и никому его не передавайте. В Windows вместо `make` можно использовать:

   ```powershell
   py -m support_copilot.server --host 127.0.0.1 --port 8000
   ```

   После запуска в другом окне PowerShell: `notepad .\data\admin.key`. Файл ключа и очередь исключены из Git. Если ключ задан через `COPILOT_ADMIN_TOKEN`, используйте его вместо файла.

   В карточке обращения выберите язык автоответа и нажмите **«Создать черновик»**. При замене ранее изменённого текста приложение попросит подтверждение. Новый текст остаётся несохранённым до нажатия «Сохранить черновик»; после проверки кнопка «Отправить оператору» делает его доступным оператору, но не отправляет игроку. Если исходного результата нет, изменились данные или правила и воспроизвести его нельзя, напишите ответ вручную.

API доступен по `POST /triage`, проверка состояния — `GET /health`. `status: ok` означает, что сервис работает, а не что кейс полностью выполнен; `knowledge_articles: 0` и предупреждение в интерфейсе указывают на отсутствие подключённых статей. Пример для локальной машины:

```bash
curl -X POST http://127.0.0.1:8000/triage \
  -H 'Content-Type: application/json' \
  -d '{"kind":"complaint","reply_language":"en","messages":[{"role":"player","text":"Игрок оскорбил меня в чате","attachments":1}]}'
```

Поле `reply_language` необязательно: допустимы `auto`, `ru`, `en`, `kk`; без него действует автоопределение. `lang` в результате остаётся определённым языком игрока, а `draft_reply.lang` показывает язык нового шаблонного ответа. Схема результата не меняется: она содержит `lang`, `category`, `priority`, `is_spam_or_duplicate`, `extracted`, `draft_reply`, `needs_human`, `confidence` и `reasons` по контракту кейса. `confidence` — **эвристическая оценка**, а не откалиброванная вероятность.

Пути к файлам и порт можно поменять:

```bash
make serve RULES=/private/rules.json TAXONOMY=/private/taxonomy.json PORT=8000
```

## Ручная проверка и ошибки обработки

- HTTP-сервис автоматически помещает в отдельную серверную очередь обращения с `needs_human: true`. Критический приоритет, низкая уверенность, неопределённый язык, возможный спам/повтор и категории обязательной проверки дополнительно направляются человеку. Текущий классификатор — эвристический baseline, не LLM; он не умеет обнаруживать все свои смысловые ошибки. Оператор может вручную отправить любое обращение через кнопку в результате.
- Если обработчик выбросил исключение или вернул некорректный результат, обращение попадает в очередь без выдуманных категории, приоритета и ответа. Если правила или таксономия не загрузились при запуске, сервер работает в режиме ручной проверки; после исправления файлов его нужно перезапустить. В интерфейсе при тайм-ауте также предпринимается отдельная попытка передачи в очередь.
- Администратор видит причину передачи и сообщение игрока, может взять обращение в работу, исправить и сохранить черновик, а затем нажать «Отправить оператору». Если игрок указал номер, в защищённой карточке появляется раскрывающийся список совпадающих пунктов из разных разделов. Это **непроверенные варианты**, а не доказательство нарушения или автоматическая цитата; администратор проверяет раздел, текст и обстоятельства. Ответ появляется в операторской очереди; игроку он автоматически не отправляется.
- Защищённый `POST /admin/api/reviews/{id}/draft` принимает только текущую `version` и `language: ru|en|kk`. Он локально формирует кандидат, не сохраняет текст в очередь и не отправляет его. Повторное построение использует только хранимое сообщение и метаданные без хеша заявителя, поэтому не добавляет событие в детектор дублей. Для старых карточек сначала проверяется, что исходный черновик, категория и приоритет воспроизводятся. При несовпадении администратор пишет ответ вручную; при изменении версии нужно обновить карточку, не потеряв правки.
- Очередь оператора, выбранное обращение, форма, черновики и идентификаторы для получения ответов сохраняются в `sessionStorage` **этой вкладки**. После обновления и перехода в админку и обратно очередь восстанавливается, а статусы переданных обращений запрашиваются снова. Она не синхронизируется между вкладками и может пропасть при закрытии вкладки, очистке данных браузера или недоступном/переполненном хранилище. При ошибке хранения показывается предупреждение; не считайте данные сохранёнными. При незавершённой операции дождитесь её результата перед переходом.
- `sessionStorage` не шифрует данные и может содержать текст игрока, введённый хеш, черновики, ответы и секретные идентификаторы доступа к статусу. Не используйте общий компьютер для личных данных и ограничьте доступ к профилю браузера. Некоторые браузеры восстанавливают закрытые вкладки вместе с хранилищем — закрытие не является надёжным стиранием. Кнопка «Очистить очередь» с подтверждением удаляет локальную очередь и доступ к ответам в этой вкладке, **не удаляя записи с сервера**. «Очистить форму» отдельно сбрасывает введённые текст, вложения и хеш. Серверные записи и скачанные выгрузки удаляются отдельно по правилам проекта.
- Кнопка «Эскалировать» сохраняет текущий черновик и помечает обращение для дополнительной проверки в той же очереди; его можно найти фильтром «Эскалации». Это внутренняя отметка: отдельные роли, назначения и внешние уведомления не подключены. Статус доступен оператору, но черновик не считается готовым ответом.
- В серверную очередь сначала попадает исходный черновик. Локальные правки оператора передаются только после нажатия «Передать правку администратору». Администратор видит их отдельно. Проверка версии не позволяет одному администратору незаметно затереть изменения другого.
- При полной недоступности сервера доставка невозможна; при обрыве связи подтверждение может потеряться. Интерфейс не объявляет такую передачу успешной и позволяет повторить попытку с тем же идентификатором без создания дубликата. Администратор должен следить за своей очередью: внешних уведомлений, SMS, Telegram и интеграции с игрой нет.
- При успешном `POST /triage` JSON результата остаётся прежним. Заголовок `X-Review-Status` содержит `queued`, `not_required` или `unavailable`; при `queued` заголовок `X-Review-Receipt` позволяет запросить `/reviews/status` через одноимённый заголовок. Он же возвращается при ошибке обработки, если обращение действительно сохранено. Идентификатор является секретом доступа к статусу и ответу: не помещайте его в URL, логи или общие чаты. При `unavailable` нельзя считать обращение доставленным. Пакетная команда `make predict` не добавляет обращения в эту очередь.

Данные серверной очереди хранятся в `data/admin-queue.sqlite3`, включая текст игрока, ограниченные метаданные, исходный результат и правки администратора. Хеши заявителей, ответы других ролей, содержимое вложений и тексты исключений не сохраняются. По умолчанию допускается до 1000 записей; заполненная очередь не удаляет действующие обращения молча. Записи старше 14 дней удаляются при следующем обращении к очереди, а администратор может удалить запись вручную. **Это не отменяет обязанности владельца удалить все данные и резервные копии в срок, установленный организаторами.**

### Обратная связь для будущего обучения

- После сохранения изменённого черновика, эскалации с правкой или отправки ответа оператору в той же базе атомарно сохраняется обратная связь. Для каждого обращения хранится **последнее** состояние: текст игрока, исходный ответ помощника (если он был), переданный оператором черновик, ответ администратора, версия и статус. Простое взятие в работу без правки обучающую запись не создаёт; отправка неизменённого ответа фиксируется как подтверждение без исправления.
- Раздел «Обратная связь» в админке выгружает записи в `admin-feedback.jsonl`. Эндпоинт `GET /admin/api/feedback/export` требует ключ администратора. В строках `approved: true` означает, что текущая версия ответа передана оператору; `false` — черновик или эскалация. `is_current: false` означает, что после сохранения сигнала карточка изменилась и требует повторной проверки. `feedback_type` различает исправленный, неизменённый и полностью человеческий ответ. Это сырая обратная связь, не гарантия правильной разметки.
- При повторном открытии завершённого обращения подтверждение снимается. Удаление или автоматическая очистка обращения удаляет и связанную запись обратной связи. **Уже скачанные выгрузки не удаляются автоматически:** они содержат обращения и ответы, поэтому храните их приватно, не коммитьте и удаляйте вместе с другими данными по срокам организаторов. Безопасно проверить обезличивание и качество перед любым использованием.
- Текущие эвристики не обучаются и не изменяются автоматически. Выгрузка — исходный материал для будущего обучения, которое необходимо отдельно разработать и оценить; не используйте неподтверждённые или устаревшие записи как готовые эталоны.

На Unix созданные файл ключа и база имеют права `600`, новая папка — `700`. На Windows проверьте права доступа к папке средствами ОС: `chmod` не заменяет настройки ACL. Ключ создаётся только на сервере, не передаётся в URL и не сохраняется в браузерном хранилище; при перезагрузке админки или уходе с неё нужно войти заново. При возврате через историю браузера ключ и карточки не восстанавливаются из back/forward cache (кроме специального изолированного демо без входа). Доступен собственный ключ в переменной окружения `COPILOT_ADMIN_TOKEN` (24–200 ASCII-символов без пробелов, буквы, цифры и `._~-`) и параметры `--admin-db`, `--admin-key-file`. Используйте отдельную учётную запись ОС и ограничьте доступ к файлам ключа и базы.

## Пакетный запуск и оценка

```bash
make predict IN=data/tickets.jsonl OUT=data/pred.jsonl
make evaluate IN=data/tickets_valid.jsonl
make benchmark IN=data/tickets_valid.jsonl REQUESTS=1000 WORKERS=1
make test
```

`predict` принимает JSONL/JSONL.GZ и простую HTML-обёртку, в которой каждый исходный JSON расположен на отдельной строке, как в присланном файле `tickets_valid-2.HTML`. Это **не универсальный HTML-парсер**: неподдерживаемая разметка и повреждённые строки вызывают ошибку. Текст вроде `<digits>` и `<url>` внутри JSON не обрабатывается как HTML и сохраняется. Выход записывается атомарно в исходном порядке; вход не перезаписывается. `-` означает stdin/stdout для обычного JSONL.

`evaluate` считает accuracy категории и macro-F1 приоритета **только по имеющейся разметке**; без неё возвращается `null`. Также выводятся число случаев, где правило требуется по *предсказанной* категории, число ответов с цитатой, доля обращений для человека и p95 локального конвейера. Наличие цитаты не подтверждает её релевантность. `benchmark` последовательно либо с указанным числом клиентов отправляет первые `REQUESTS` обращений временному локальному HTTP-серверу с отдельной временной SQLite-очередью. Считаются статусы, подтверждения передачи и p50/p95/p99, без браузера, внешней сети и стоимости инфраструктуры. Временная база удаляется после штатного завершения; это не production SLA.

Для Windows без `make` (файлы должны находиться локально в `data/`):

```powershell
py -m support_copilot.batch --in .\data\tickets_valid-2.HTML --out .\data\pred.jsonl
py -m support_copilot.evaluate --in .\data\tickets_valid-2.HTML
py -m support_copilot.benchmark --in .\data\tickets_valid-2.HTML --requests 1000 --workers 1
```

### Локальное исследование обращений и ответов

```bash
make audit IN=data/tickets_valid-2.HTML
# без make, в том числе в Windows:
python -m support_copilot.audit --in data/tickets_valid-2.HTML
```

Команда локально считает категории, длину сообщений, наличие источников и простые признаки в исторических ответах администраторов. В выводе нет текстов, ников, ID и отдельных примеров; сами файлы и результаты всё равно хранятся приватно. Упомянутый историческим ответом номер может относиться к другому разделу; совпадение номеров **не является меткой релевантности или точности**. Ответы и поля `verdict`/`punishment`/`violation` используются только для агрегированного аудита, но не как признаки нового обращения. Доработки выполнялись с изучением этой же выборки: полученные показатели не являются независимой валидацией.

### Независимая ручная оценка

Следующие команды создают **приватные** выборки одного и того же размера с одним seed. Первая не содержит результатов модели и предназначена для независимой разметки, вторая — для оценки черновиков другим проверяющим:

```bash
make review IN=data/tickets_valid-2.HTML OUT=data/blind-labels.jsonl COUNT=100 SEED=42 BLIND=1
make review IN=data/tickets_valid-2.HTML OUT=data/draft-reviews.jsonl COUNT=100 SEED=42
# После ручного заполнения:
make evaluate IN=data/tickets_valid-2.HTML LABELS=data/blind-labels.jsonl REVIEWS=data/draft-reviews.jsonl
```

То же в PowerShell:

```powershell
py -m support_copilot.review_pack --in .\data\tickets_valid-2.HTML --out .\data\blind-labels.jsonl --count 100 --seed 42 --blind-labels
py -m support_copilot.review_pack --in .\data\tickets_valid-2.HTML --out .\data\draft-reviews.jsonl --count 100 --seed 42
# После ручного заполнения:
py -m support_copilot.evaluate --in .\data\tickets_valid-2.HTML --labels .\data\blind-labels.jsonl --reviews .\data\draft-reviews.jsonl
```

Наборы выбираются детерминированно по хешу `ticket_id` и seed, без стратификации; вход должен иметь уникальные `ticket_id`. Для поиска примеров языка можно дополнительно задать `REVIEW_LANG=kk` (или `--language kk`): фильтр использует **эвристически определённый** язык, поэтому носитель должен проверить язык сам. Отдельно наберите и оцените примеры KK/UZ, а также смешанные и короткие сообщения; общая выборка не гарантирует их представительства.

В `blind-labels.jsonl` человек заполняет только `review.category` и `review.priority` допустимыми кодами таксономии. В `draft-reviews.jsonl` другой проверяющий заполняет `review.draft_rating` от 1 до 5, где 1 — опасный/неверный ответ, 3 — безопасный, но неполный, 5 — корректный черновик; `review.citations_relevant` — `true`, только если каждую нужную ссылку проверили на существование и строгую релевантность, `false` при неверной или отсутствующей обязательной ссылке, `null` если ссылка не нужна. `review.language_rating` — оценка языка 1–5, `review.reviewer_native` — собственная отметка носителя (`true`/`false`). Незаполненные поля оставляют `null`; они не превращаются в положительную оценку.

Не изменяйте `source`, `draft_reply` и поля хешей: программа сопоставляет их с исходным обращением и конкретным черновиком и отклоняет устаревшие оценки. Хеши защищают от случайного несовпадения, а не удостоверяют личность проверяющего. Ручная выборка содержит текст игроков — не коммитьте и не публикуйте её, ограничьте доступ и удалите по условиям кейса. Результаты актуального запуска приведены в [REPORT.md](REPORT.md).

### Необязательная браузерная проверка

Основные тесты `make test` не требуют Node.js. Для сквозной проверки очереди, возврата из админки, языков и ошибок `sessionStorage` можно запустить `tests/browser_session_i18n.cjs`; `tests/browser_knowledge_status.cjs` дополнительно проверяет предупреждение о базе знаний, три ширины и доступность обеих страниц через axe. `tests/browser_rule_candidates.cjs` проверяет защищённый просмотр вариантов пунктов, сохранность оригинального текста, локализации и доступность. `tests/browser_reply_language.cjs` проверяет выбор языка ответа, сохранность оригинала и правок, гонку версий и ручной резервный сценарий. Нужны Node.js, `puppeteer-core`, `axe-core` и Chromium. Тесты создают синтетические обращения, поэтому запускайте их **только на отдельной тестовой базе**, а не на рабочем сервере. Пример для Linux/macOS с уже установленным Chromium:

```bash
npm install --prefix /tmp/copilot-browser-deps puppeteer-core axe-core
mkdir -p /tmp/copilot-e2e-fixtures
python3 -c 'import sys; sys.path.insert(0, "tests"); from helpers import write_fixtures; write_fixtures("/tmp/copilot-e2e-fixtures")'
COPILOT_ADMIN_TOKEN=synthetic-integration-admin-key-12345 \
  python3 -m support_copilot.server --host 127.0.0.1 --port 8012 \
    --rules /tmp/copilot-e2e-fixtures/rules.json --taxonomy /tmp/copilot-e2e-fixtures/taxonomy.json \
    --admin-db /tmp/copilot-e2e.sqlite3
# В другом терминале:
NODE_PATH=/tmp/copilot-browser-deps/node_modules CHROME_PATH=/path/to/chromium \
  TEST_ADMIN_KEY=synthetic-integration-admin-key-12345 node tests/browser_session_i18n.cjs
NODE_PATH=/tmp/copilot-browser-deps/node_modules CHROME_PATH=/path/to/chromium \
  node tests/browser_knowledge_status.cjs
NODE_PATH=/tmp/copilot-browser-deps/node_modules CHROME_PATH=/path/to/chromium \
  TEST_ADMIN_KEY=synthetic-integration-admin-key-12345 node tests/browser_rule_candidates.cjs
NODE_PATH=/tmp/copilot-browser-deps/node_modules CHROME_PATH=/path/to/chromium \
  TEST_ADMIN_KEY=synthetic-integration-admin-key-12345 node tests/browser_reply_language.cjs
```

`TEST_BASE_URL` можно задать для другого адреса изолированного тестового сервера. Не используйте реальный ключ. Тестовая база и загруженные зависимости не входят в репозиторий.

## Как работает MVP

- При классификации используются текст игрока, примеры и категории из `taxonomy.json` и небольшой набор многоязычных эвристик. Ответы администраторов и поля `verdict`, `punishment`, `violation`, `category` и `priority` **не используются как признаки** при предсказании.
- Поиск — локальный извлекающий RAG: нумерованные пункты выделяются из `rules.json`, кандидаты ограничиваются правилами категории, а затем ранжируются по совпадению слов и контексту. Для неклассифицированной жалобы единственный упомянутый игроком номер может лишь сузить поиск при дополнительном совпадении значимых слов; он сам по себе не доказывает релевантность. Равнозначные совпадения не разрешаются произвольно, повтор одного номера в одном разделе вызывает ошибку загрузки вместо выбора наугад. Администратор отдельно видит возможные пункты по указанным номерам во всех разделах, без их автоматического подтверждения.
- Раздел RP-терминов может содержать реальные определения без номеров: при явном или достаточно конкретном описании сервис показывает оригинальный термин и ID исходного раздела. **ID раздела не является номером пункта и не попадает в `draft_reply.cited`.** Если требуемый нумерованный пункт не найден, черновик остаётся неполным и обязательным для проверки. Эвристическое совпадение и наличие источника не заменяют экспертную проверку.
- Предположения игрока и его ссылки на правила не считаются доказанными фактами. `has_evidence: true` означает, что доказательства упомянуты игроком или указаны в метаданных вложений; поле `reasons` поясняет разницу. Отрицания вроде «скриншотов нет» учитываются, если метаданные не указывают на вложение. Содержимое скриншотов сервис не видит ни при каком значении поля. В `server` возвращается строковый идентификатор сервера, а при его отсутствии — явно указанная `region`.
- Используются короткие шаблоны RU/KK/UZ/EN/ES/PT. Для казахского текста учитываются замены символов из условия. Английский, испанский и португальский определяются эвристически; короткие и смешанные сообщения могут быть определены неверно.
- Платежи, подозрения на взлом и блокировки, **которые удалось распознать**, направляются человеку. Все жалобы и почти все другие обращения тоже требуют проверки; автоматическое уточнение допускается только для простого приветствия. Неясные просьбы о помощи передаются человеку. Распознавание эвристическое и не гарантирует выявление всех рискованных формулировок.
- Пятый похожий тикет того же `reporter_hash` за час помечается как дубликат. Состояние хранится в памяти процесса, без текста сообщений; без хэша заявителя, между разными процессами и после перезапуска надёжного обнаружения дубликатов нет. Для пакетной обработки вход должен идти по возрастанию `created_at`, иначе более поздние обращения не учитываются как предыдущие.
- Интерфейс позволяет редактировать и копировать черновики. Локальная очередь оператора привязана к текущей вкладке и сохраняется при её обновлении и переходах; переданные на ручную проверку обращения, ответы администратора и последняя версия обратной связи сохраняются в отдельной серверной очереди. Интеграции с игрой, отправки игрокам и автоматического обучения пока нет.

### База знаний, требуемая кейсом

Отдельная реальная база знаний пока не была приложена. Без неё сервис работает в неполном режиме: интерфейс показывает предупреждение, а обращения, которым нужна справочная статья, помечаются для ручной проверки. Для выполнения требования нужна база от организаторов или владельца проекта. Сервис умеет загружать локальный файл с проверенными статьями формата ниже; содержание здесь только синтетический пример:

```json
{
  "articles": [
    {"id": "sample-1", "title": "Справочная статья", "text": "Текст проверенной инструкции.", "categories": ["report.question"]}
  ]
}
```

`data/knowledge.json` автоматически загружается при наличии; другой путь задаётся `--knowledge`, переменной `KNOWLEDGE_PATH` или `make serve KNOWLEDGE=/private/knowledge.json`. У каждой статьи нужны уникальные непустые строки `id`, `title`, `text` и необязательный список `categories` с кодами таксономии; `approved: false` исключает статью. Неверный формат не превращается в глобальную статью: сервис сообщает об ошибке и переключается на ручную очередь.

Статья подбирается по категории и словам независимо от поиска правил. Совпасть должен **сам отрывок**, а не только название или другая часть статьи; при равнозначных отрывках сервис воздерживается. Оригинал не переводится автоматически. Если у статьи указан `source_url`, в черновике показывается ссылка. Материалы, похожие на обещания денежных действий, наказаний или запросы секретов и личных данных, консервативно не цитируются. Это фильтр, а не гарантия безопасности и релевантности: источник должен быть подтверждён владельцем, а ответ — проверен человеком.

#### Официальные публичные источники и необязательный импорт

Изучены статьи справочного центра Grand Mobile о [жалобах](https://support.grnd.gg/ru/articles/11071798), [подаче жалобы](https://support.grnd.gg/ru/articles/11071809), [апелляциях](https://support.grnd.gg/ru/articles/11071819), [подаче апелляции](https://support.grnd.gg/ru/articles/11071824), [обмене](https://support.grnd.gg/ru/articles/11918168), [доступе к аккаунту](https://support.grnd.gg/ru/articles/11029944), [защите аккаунта](https://support.grnd.gg/ru/articles/11029952), [помощи в игре](https://support.grnd.gg/ru/articles/12342952), [подключении к серверу](https://support.grnd.gg/ru/articles/12802228) и [английская инструкция](https://support.grnd.gg/en/articles/11163867). Публичные статьи не заменяют выданный `rules.json` и не подтверждают актуальность правил в конкретном кейсе.

На своём компьютере можно **по отдельной команде** подготовить приватный черновик базы из фиксированного списка официальных URL:

```bash
python -m support_copilot.official_knowledge --download --out data/official-knowledge.draft.json
```

Будут выполняться только HTTPS GET-запросы к `support.grnd.gg`: тексты обращений и ответов администраторов в них не передаются, но сайт увидит обычные сетевые данные запроса, включая IP. Все полученные статьи изначально имеют `approved: false` и не используются. Владелец должен проверить право использования, актуальность, язык, каждую статью и категорию, удалить неподходящие материалы и вручную установить `approved: true` у одобренных. Затем можно явно подключить файл: `make serve KNOWLEDGE=data/official-knowledge.draft.json` или `py -m support_copilot.server --knowledge .\\data\\official-knowledge.draft.json` в Windows. Файл не перезаписывается при повторном импорте и исключён из Git; при изменении источника его нужно повторно проверять.

Парсер и защитные ограничения импорта проверены на синтетическом HTML. **Прямое скачивание в этой рабочей среде не проверено из-за сетевых ограничений**; если сайт изменил разметку или недоступен, создайте проверенный `knowledge.json` вручную. Загрузка публичных статей не доказывает выполнение требования организаторов о базе знаний и не снимает необходимость проверки человеком.

## Конфиденциальность и ограничения

Папка `data/`, JSONL и типичные файлы результатов исключены из Git. Не публикуйте исходные файлы, содержимое обращений, цитаты из набора, предсказания или производные выборки; проверяйте `git status` перед публикацией. Данные предназначены только для кейса и должны быть удалены в течение 14 дней после объявления победителей, если нет отдельного соглашения. При обработке обращения внешние API и сеть не используются; отдельно запускаемый импорт публичных справочных страниц описан выше.

В приложенной таксономии указано, что она черновая. До сдачи стоит уточнить у организаторов её окончательную версию и наличие размеченных категорий и приоритетов в валидации: описание датасета и пример схемы в задании противоречат друг другу.

Встроенный HTTP-сервер предназначен для демонстрации в доверенной среде. Админка защищена одним локальным ключом, но полноценного управления пользователями, TLS, аудита, резервирования, независимого канала доставки и аутентификации обычного `/triage` нет. `make serve` слушает `0.0.0.0` для предпросмотра; для работы на своём ПК используйте команду с `--host 127.0.0.1`. Не размещайте приложение в открытом доступе с данными кейса; перед реальным использованием нужны защищённый сервер, отдельные учётные записи и роли, HTTPS, контроль доступа, проверка безопасности и оценка на реальной разметке.
